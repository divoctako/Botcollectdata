# แบบระบบบอตบันทึก LINE

สถานะ: ผู้ใช้อนุญาตให้พัฒนาแล้ว มีโค้ดและทดสอบในเครื่อง ยังไม่ได้ deploy หรือเชื่อมบัญชี LINE/Google จริง ดูวิธีตั้งค่าใน README

## ข้อกำหนดหลัก

รองรับกรอบเริ่มต้น 50 กลุ่ม รวมประมาณ 10,000 ข้อความตัวอักษรต่อวัน ใช้บริการฟรีเท่านั้น ไม่ดึงประวัติก่อนบอตเข้ากลุ่มและระบบพร้อมรับข้อความ

## โครงสร้างที่เสนอ

1. LINE Official Account ใหม่ ส่ง webhook ไปยัง API บน Cloudflare Workers แผนฟรี
2. API ตรวจลายเซ็น LINE ก่อนรับข้อมูล และเขียนข้อความลง Google Sheets ทันที ไม่รอรอบส่งประจำวัน
3. เสนอ Cloudflare D1 แผนฟรีสำหรับข้อมูลควบคุมการกันซ้ำ/กู้คืนและรายการที่ส่งไม่สำเร็จเท่านั้น ไม่ใช่ที่พักข้อความเพื่อรอเวลา 08:00 น. ยกเลิก Cron ส่งข้อความประจำวันแล้ว
4. หน้า frontend ใช้ Workers Static Assets บน Cloudflare แสดงเวลาที่บันทึกสำเร็จล่าสุด จำนวนรายการส่งไม่สำเร็จ สถานะและข้อผิดพลาด เสนอให้ปุ่ม reload รีเฟรชสถานะและสั่งลองส่งรายการล้มเหลวทั้งหมด
5. เสนอเข้าสู่ระบบด้วย Google และจำกัดผู้ใช้งานไว้ที่บัญชีเจ้าของเท่านั้น
6. Google Sheets แยกไฟล์รายเดือนตามเวลาส่งในไทย แต่ละไฟล์แยกแท็บตามรหัสกลุ่ม พร้อมไฟล์สารบัญ

## พฤติกรรมข้อมูล

โครงสร้างตารางและ view ตามคำขอผู้ใช้ระบุใน [data-model.md](data-model.md) และ migration `migrations/0001_chat_messages.sql` มี runtime tables สำหรับพิกัดชีต OAuth สถานะ และ lease ใน migration 0002 รวมถึงดัชนีสำหรับ cleanup ใน 0003 โค้ดพร้อมรันในเครื่อง ยังไม่เชื่อม Cloudflare/LINE/Sheets จริง

- บันทึกวัน เวลา ผู้ส่ง ข้อความ และรหัสที่ใช้ระบุข้อความ/กลุ่ม พร้อมสถานะที่เกี่ยวข้อง
- เก็บทั้งข้อความเดิมและฉบับแก้ไขพร้อมเวลาแก้ไข
- เมื่อยกเลิกส่ง ให้คงเนื้อหาเดิมและทำเครื่องหมายยกเลิกส่งตามความต้องการผู้ใช้
- หากชื่อผู้ส่งไม่มี ให้แสดงว่าไม่ทราบผู้ส่ง พร้อมรหัสผู้ส่งหาก LINE ส่งมา ไม่สร้างชื่อขึ้นเอง
- การกดปุ่มลองส่งเฉพาะรายการล้มเหลว ไม่ดึงประวัติ LINE ใหม่และไม่สร้างข้อมูลที่บันทึกสำเร็จแล้วซ้ำ
- ประสานการเขียนระหว่าง webhook และคำสั่งลองใหม่ มี checkpoint เพื่อเริ่มต่อหลังขัดข้อง
- เมื่อเขียนชีตไม่สำเร็จ ให้เก็บรายการกู้คืนและลองใหม่แบบหน่วงเวลา ภายในข้อจำกัดเวลารัน หากยังไม่สำเร็จให้แสดงสถานะ คงข้อมูลไว้สำหรับการกดปุ่มหรือ job กู้คืนอัตโนมัติที่แยกจากเส้นทางเขียนทันที
- เก็บประวัติในชีตย้อนหลัง 1 ปี ลบรายการที่เก่ากว่าอัตโนมัติ ข้อมูลควบคุมการส่งซ้ำและกู้คืนเก็บเท่าที่จำเป็น ไม่เก็บสำเนาข้อความทั้งปีโดยไม่มีเหตุผล
- เป้าหมายเขียนทันทีขึ้นกับเครือข่ายและโควตา API เมื่อมีข้อความกระจุกตัวหรือเกิดข้อผิดพลาดอาจต้องหน่วงแล้วลองใหม่ ไม่รับประกันว่าไม่มีความล่าช้า

## ขอบเขตบริการฟรี

Cloudflare Workers Free มีโควตาคำขอแบบไดนามิก 100,000 ครั้งต่อวันและ CPU 10 ms ต่อการเรียก จึงต้องใช้โค้ดเบาและแบ่งงานกู้คืน/ลบข้อมูลเป็นชุดเล็ก Requests ที่ให้บริการไฟล์ static โดยตรงฟรีและไม่จำกัดตามเอกสารปัจจุบัน ต้องตรวจโควตาทุกส่วนก่อนใช้งานจริง

Cloudflare D1 Free มีโควตารวมอ่าน 5 ล้านแถว/วัน เขียน 100,000 แถว/วัน และขนาดฐานข้อมูลเดี่ยวสูงสุด 500 MB ต้องนับผลของดัชนีและการลบ/แก้ไขด้วย จึงต้องตรวจการใช้จริง ไม่ถือว่าจำนวนข้อความเพียงอย่างเดียวรับประกันว่าจะอยู่ในโควตา

ใช้เฉพาะแผนฟรี ไม่เปิดอัปเกรดหรือคิดเงินอัตโนมัติ เมื่อชนโควตาอาจรับหรือส่งข้อมูลต่อไม่ได้ ต้องแสดงสถานะจริง และอาศัยการส่งซ้ำจาก LINE เท่าที่ LINE รองรับ ไม่อ้างว่ากู้คืนข้อความที่ระบบไม่เคยได้รับได้

ก่อนเริ่มใช้งานจริงต้องทดสอบการรับ webhook การกันซ้ำ การเริ่มต่อหลังล้มเหลว การเขียนชีตแบบแบ่งชุด และปริมาณงานตัวอย่างภายในโควตาฟรี

ข้อจำกัดที่พบระหว่างพัฒนา: แบบนี้มีการเขียนหลายแถวต่อข้อความ รวมข้อความ/เหตุการณ์ พิกัด การยืนยันส่ง และการล้าง cache จึงคาดว่าจะเกิน D1 Free 100,000 แถวเขียนต่อวันที่ 10,000 ข้อความ/วันต่อเนื่อง ต้องปรับสถาปัตยกรรม/ลดการเขียนเพิ่มเติมก่อนถือว่าผ่านเป้าปริมาณกับงบฟรี การทดสอบข้อมูลสังเคราะห์ในเครื่องไม่ได้พิสูจน์โควตา edge จริง

## บัญชีและการตั้งค่าที่ต้องใช้ภายหลัง

- LINE Official Account และ Messaging API
- Google สำหรับ Sheets/Drive และการเข้าสู่ระบบ
- Cloudflare Workers Free สำหรับเว็บและ API รวมถึง D1 ตามแบบเสนอ ไม่ต้องใช้ Vercel

เก็บรหัสลับฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ใส่ใน frontend หรือเอกสาร และไม่ให้ผู้ใช้ส่งรหัสลับลงแชท
