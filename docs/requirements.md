# ข้อกำหนดบอตบันทึกข้อความ LINE

สถานะ: ผู้ใช้อนุญาตให้เริ่มพัฒนาตามเอกสารแล้ว มีโปรแกรม Workers/frontend พร้อมการทดสอบในเครื่อง ยังไม่เชื่อมบัญชีหรือ deploy จริง

## ข้อสรุปที่ผู้ใช้ยืนยัน

- รับข้อความจากกลุ่ม LINE ที่เชิญบอตเข้าร่วม
- แยกแท็บ Google Sheets ตามกลุ่มต้นทาง
- เริ่มเก็บข้อความใหม่ตั้งแต่บอตเข้ากลุ่ม โดยระบบรับข้อความต้องพร้อมทำงาน ไม่ดึงประวัติก่อนหน้านั้น
- เก็บเฉพาะข้อความตัวอักษรที่สมาชิกคุยกัน ไม่จัดเก็บไฟล์สื่อ
- บันทึกว่าใครส่งข้อความอะไร พร้อมวันและเวลาส่ง
- โครงสร้างข้อมูลตามคำยืนยันล่าสุด: group_id, message_id, sender_id, sender_display_name, วันเวลาส่งพร้อมเขตเวลาไทย, เนื้อหา, replied_to_message_id เมื่อ LINE ส่งมาให้ และสถานะแก้ไข/ยกเลิกส่ง
- แยกข้อความหลักออกจากประวัติการเปลี่ยนแปลง ให้การวิเคราะห์ AI นับหนึ่งข้อความต่อรหัสข้อความ ไม่เพิ่มจำนวนตามฉบับแก้ไข ดูรายละเอียดใน data-model.md และ migration 0001_chat_messages.sql
- ใช้กรอบออกแบบเริ่มต้น 50 กลุ่ม รวมประมาณ 10,000 ข้อความต่อวัน
- แยกไฟล์ Google Sheets รายเดือน พร้อมไฟล์สารบัญรวมลิงก์ แต่ละไฟล์แยกแท็บตามกลุ่มและผูกกับรหัสกลุ่มเพื่อแยกกลุ่มชื่อซ้ำหรือเปลี่ยนชื่อ (ผู้ใช้ยืนยันข้อ 13 แทนข้อกำหนดไฟล์เดียวเดิม)
- เริ่มสร้าง LINE Official Account ใหม่สำหรับบอตนี้ และตั้งค่า Messaging API
- เมื่อได้รับเหตุการณ์ยกเลิกส่ง ให้เก็บเนื้อหาข้อความเดิมไว้พร้อมทำเครื่องหมายว่าถูกยกเลิกส่ง ตามคำยืนยันของผู้ใช้ รูปแบบเครื่องหมายยังไม่ได้สรุป
- ใช้บริการฟรีเท่านั้น ไม่สมัครแผนเสียเงินโดยอัตโนมัติ
- เขียนข้อความลง Google Sheets ทันทีเมื่อได้รับจาก LINE ไม่พักเพื่อรอรอบประจำวัน และยกเลิกรอบส่งข้อมูลเวลา 08:00 น. ตามคำขอล่าสุด
- คงหน้า frontend สำหรับดูสถานะและปุ่ม reload โดยเสนอให้รีเฟรชสถานะและลองส่งรายการที่เขียนไม่สำเร็จ ไม่เพิ่มข้อมูลที่บันทึกแล้วซ้ำ
- บัญชี Google ของผู้ใช้เป็นเจ้าของไฟล์ ผู้ใช้เป็นคนเดียวที่เปิดดูได้ในระยะแรก (ระบบยังต้องได้รับสิทธิ์เขียนข้อมูล)
- เก็บข้อมูลย้อนหลัง 1 ปี และลบข้อมูลเก่ากว่านั้นอัตโนมัติ
- เก็บข้อความเดิมและข้อความใหม่พร้อมเวลาแก้ไขเมื่อได้รับเหตุการณ์แก้ไขข้อความ
- เมื่อเขียนชีตไม่สำเร็จ ให้พักข้อมูลแล้วลองใหม่อัตโนมัติพร้อมป้องกันรายการซ้ำ
- ใช้ Cloudflare แทน Vercel ทั้ง frontend และ API ตามคำขอล่าสุด โดยวาง frontend บน Workers Static Assets และ API บน Workers Free
- ผู้ใช้ยืนยันว่าเป็นการใช้งานส่วนตัว

## การตั้งค่าก่อนใช้งานจริง

- ตั้ง OWNER_EMAIL, Google OAuth และ LINE secrets โดยไม่ส่งรหัสลับลงแชท
- สร้าง D1 ในบัญชี Cloudflare และใส่ database_id จริงตาม README
- โปรแกรมสร้างไฟล์สารบัญและไฟล์รายเดือนใน Drive ของเจ้าของเอง สถานะยกเลิกส่งใช้ message_status=unsent
- ทบทวนข้อจำกัดที่ยังไม่ผ่าน: แบบ D1 ปัจจุบันคาดว่าจะเกินโควตาเขียนฟรีที่ปริมาณ 10,000 ข้อความ/วันต่อเนื่อง เนื่องจากมีการเขียนหลายแถวและดัชนีต่อข้อความ ยังไม่ควรใช้งานเต็มเป้าโดยอ้างว่าฟรีรองรับครบ

## ผลตรวจความจุระหว่างออกแบบ

- ที่ 10,000 ข้อความต่อวัน จะมีประมาณ 3,650,000 ข้อความต่อปี
- ตัวอย่างหากใช้ 10 คอลัมน์ต่อข้อความ ต้องใช้ประมาณ 36,500,000 เซลล์ ไม่รวมส่วนหัวและพื้นที่อื่น จึงไม่เหมาะกับไฟล์เดียวตลอดปี
- Google ประกาศเพิ่มเพดาน Google Sheets เป็น 20 ล้านเซลล์ต่อไฟล์ในเดือนกันยายน 2026 ขณะที่หน้า Help ยังระบุ 10 ล้านเซลล์ ควรเผื่อข้อจำกัดและแบ่งไฟล์ก่อนเต็ม
- ผู้ใช้ยืนยันแยกไฟล์รายเดือน แต่ละไฟล์ยังแยกแท็บตามกลุ่ม มีไฟล์สารบัญรวมลิงก์
- Cloudflare เป็นที่รันเว็บและ webhook ตามคำขอล่าสุด ไม่ใช้ D1 พักข้อความเพื่อรอรอบประจำวันแล้ว ข้อเสนอปัจจุบันคือใช้เฉพาะข้อมูลควบคุมการกันซ้ำ/กู้คืนและรายการส่งไม่สำเร็จ เพื่อรักษาข้อกำหนดลองส่งใหม่

## ข้อจำกัด Cloudflare ที่ต้องคำนึงถึง

- Workers Free รับคำขอแบบไดนามิกได้ 100,000 ครั้งต่อวัน และมี CPU 10 ms ต่อการเรียก ต้องทดสอบปริมาณจริงและแบ่งงานเป็นชุดเล็ก
- D1 มีโควตาแยกด้านจำนวนแถวอ่าน/เขียนและพื้นที่ ต้องรวมงานกันซ้ำและลองส่งใหม่ในการประเมิน
- ไม่มี Cron ส่งข้อความประจำวันแล้ว อาจใช้ Cron แยกสำหรับลบข้อมูลเกินอายุหรือกู้คืนรายการส่งไม่สำเร็จ
- ข้อมูลกู้คืนรายการส่งไม่สำเร็จต้องอยู่ในที่เก็บถาวร ไม่อาศัยหน่วยความจำฟังก์ชันข้ามคำขอ

## ข้อจำกัดที่ตรวจจากเอกสาร LINE

- แต่ละกลุ่มมี LINE Official Account ได้หนึ่งบัญชีในเวลาเดียวกัน และต้องเปิดให้บอตเข้ากลุ่ม
- ไม่มีช่องทางใน Messaging API สำหรับดึงประวัติข้อความทั้งกลุ่มย้อนหลัง ข้อสรุปนี้อิงจากขอบเขต API ที่ให้บริการ
- ข้อมูลผู้ส่งอาจไม่ครบ จึงรับประกันชื่อผู้ส่งทุกข้อความไม่ได้
- Webhook อาจส่งซ้ำหรือมาถึงผิดลำดับ
- LINE แนะนำให้ลบเนื้อหาที่จัดเก็บเมื่อได้รับเหตุการณ์ยกเลิกส่ง

ผู้ใช้เลือกเก็บเนื้อหาข้อความที่ยกเลิกส่งไว้และทำเครื่องหมาย จึงแตกต่างจากแนวทางที่ LINE แนะนำข้างต้น
